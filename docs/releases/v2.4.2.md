KeepClip Update - v2.4.2

- Improved privacy and security around the library, video playback, clip deletion, cloud operations and recording controls. Private requests now require an authenticated owner session. The desktop app handles this automatically, without an extra sign-in step.
- Added protection against requests from untrusted websites and other local ports. Network access in server-only mode now requires explicit configuration, authentication and HTTPS.
- Fixed unsafe handling of cloud media. KeepClip rejects HTML, SVG and unsupported content returned in place of a video, and prevents that content from running scripts on the app's origin. Active SVG profile images are also rejected.
- Updated Google Drive authorization to use public Desktop client settings with PKCE. New installers include only the public client ID, and packaging rejects configurations containing extra fields or a client secret.
- Reduced memory usage during audio extraction and added a 30-minute transcription limit. Oversized decoded audio is rejected instead of consuming unbounded memory or producing a silently truncated transcript.
- Improved cancellation of transcription. Cancelling stops the current decoder and preserves the previous transcript instead of replacing it with incomplete results.
- Added protection against folder-link loops and excessive directory scans. Failed or interrupted enumeration preserves the existing library records.
- Expanded regression tests, including real WebView2, FFmpeg, server authentication and installer checks.

For server-only users: set `KEEPCLIP_API_TOKEN` before startup. Remote access additionally requires `KEEPCLIP_ALLOW_REMOTE=1` and an explicit HTTPS listener. See the [private API instructions](https://github.com/Kamilr210/KeepClip/blob/v2.4.2/docs/private-api.md). Normal desktop use does not require manual configuration.

Download **KeepClip-Setup.exe** below to install or update. Technical files are available separately; they are not required to run the app.
